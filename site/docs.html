概览

Oriel 是一个 macOS 风格的 Windows 文件管理器。界面由 React 19 画在 Tauri 的 WebView2 里，文件操作交给本机的 Fastify 服务；两者通过 HTTP 和 SSE 通信，全部监听 127.0.0.1，不依赖任何云端。

因为它只是一个普通网页加上一个本地服务，所以同一份界面既能在 Tauri 窗口里跑，也能在浏览器里 npm run dev 直接调试。

当前版本已经打通：浏览、导航、流式搜索、多选、新建 / 重命名 / 复制 / 剪切 / 粘贴 / 删除、 拖放移动、归档浏览与解压、后台传输、回收站、撤销、预览面板、批量重命名、设置与自更新。

技术栈

层 选型
桌面外壳 Tauri 2（无边框窗口 + 自绘红绿灯；Rust 侧通过 windows crate 调 Shell COM）

契约 packages/shared 中的共享 DTO 与常量

架构

Tauri 窗口 (WebView2)
   └── React 19 SPA（页面、主题、交互全在这里）
          │  HTTP /api（JSON）
          │  SSE  /events、/fs/search/stream
          ▼
     Fastify REST（127.0.0.1:8787）
          ├── node:fs / trash      → 本地文件系统
          ├── PowerShell           → 磁盘信息、剪贴板、字体
          ├── 7-Zip CLI            → 归档读写
          └── sharp                → 图片缩略图

几个关键取舍

  • 服务只监听回环地址：CORS 只放行 Tauri 源与 Vite 开发源，其它 Origin 一律 403，避免本机任意网页调用这些文件操作接口。
  • 长路径：超过 260 字符的路径自动加 \\?\ 前缀 （server/src/lib/native-fs.ts），不依赖系统的 LongPathsEnabled。
  • 剪贴板：常驻一个 PowerShell STA 宿主，通过 stdin/stdout 一次一行 JSON 往返；每次新起进程要 400ms，太慢，这样读写都在 10–30ms。
  • Shell 菜单串行化：第三方 Shell 扩展不是线程安全的，右键菜单的 COM 调用排成单队列，避免堆损坏。
  • 搜索：深度优先而非广度优先，10 秒预算、80 万条目上限，跳过 WinSxS / DriverStore 这类目录，结果通过 SSE 边搜边推。

快速开始

需要 Node 22 与 Rust（只有跑桌面版才需要 Rust）。

npm install

# 1) 只跑浏览器版（最快，用来调界面）
npm run dev            # 打开 http://localhost:5173

# 2) 跑桌面版（会自动等 8787 与 5173 就绪）
npm run dev:desktop

桌面版会启动 Tauri 窗口并连接同一个 REST 服务。图标里的 Office / PDF / 可执行文件图标需要 Windows 环境，在纯浏览器里会退化成自绘图标。

REST API

统一前缀 /api，错误响应为 { "error": { "code", "message" } }。 路径必须是绝对路径；删除磁盘根目录、Windows、Program Files、 ProgramData、用户目录根等系统目录会被拒绝。

方法 路径 说明
GET/health健康检查
GET/system/info平台、主机名、home、版本
GET/drives磁盘列表（容量 / 标签 / 类型）
GET/special个人、桌面、下载、图片等快捷目录
GET/system/fonts已安装字体族（10 分钟缓存）
GET/app/update检查 GitHub Releases
GET/fs/list?path=&showHidden=列目录（文件夹优先、自然排序）
GET/fs/stat?path=单条信息
GET/fs/preview?path=文本预览（512 KB 上限）
GET/fs/info?path=图片分辨率、PDF 页数、只读 / 链接
GET/fs/size?path=文件夹递归大小（worker + 60s 缓存）
POST/fs/sizes批量查询，最多 3 个并发遍历
GET/fs/media?path=音视频内联流，支持 Range（206）
GET/fs/search?path=&q=递归搜索（10 秒预算，可中止）
GET/fs/search/streamSSE 流式搜索：progress / matches / done
GET/fs/thumbnail?path=&size=图片缩略图（webp，磁盘 + 内存缓存）
POST/fs/icons从 Windows Shell 提取真实图标
POST/fs/entries只 stat 指定子项（增量补丁用）
GET/fs/resolve?path=展开 ~、%VAR%
POST/fs/conflicts同名冲突列表
POST/fs/transfer后台复制 / 移动任务
GET/events?watch=SSE：目录变更与所有任务进度
POST/fs/mkdir新建文件夹
POST/fs/new-file新建文本文件（带初始内容）
POST/fs/new-office-file新建 docx / xlsx / pptx（服务端生成 OOXML 包）
POST/fs/rename单个重命名
POST/fs/batch-rename批量改名：全量校验 + 两步改名
POST/fs/copy · /fs/move同步复制 / 移动
POST/fs/delete默认进回收站，可永久删除
POST/fs/clipboard把文件列表写进 Windows 剪贴板（CF_HDROP）
GET/fs/clipboard读系统剪贴板里的文件列表
POST/archive/extract · /archive/create解压 / 打包（7-Zip）
GET/recycle回收站列表（解析 $Recycle.Bin 的 $I 元数据）
POST/recycle/restore · purge · empty还原 / 永久删除 / 清空

界面能力

浏览与选择

  • 图标网格与列表两种视图，可切换图标大小、列表密度，每个文件夹各记一份
  • 单选、Ctrl 多选、Shift 连选、方向键移动、滚动跟随、空格预览
  • 按名称 / 种类 / 日期 / 大小分组，列表视图的分组头吸顶并显示计数
  • 面包屑可编辑（Ctrl+L），支持 ~、%TEMP%、$HOME

文件操作

  • 新建文件夹与 11 种常用文件；Office 三件套是服务端生成的真 OOXML 包
  • 单个与批量重命名（查找替换 / 编号 / 添加文本 / 大小写），带实时预览与冲突检测
  • 复制 / 剪切 / 粘贴，与 Windows 剪贴板双向互通，能直接粘到微信或 QQ
  • 拖放移动，按住 Ctrl 为复制；悬停 600ms 自动展开目标文件夹
  • 删除默认进回收站，永久删除需二次确认；撤销栈保留 20 步
  • 右键菜单分文件夹 / 文件 / 空白处三套，可逐项开关并与系统菜单项合并

归档

  • 识别 7-Zip，把 zip / 7z / rar 当成只读目录浏览
  • 可以只解压其中几项，也可以把选中项打包成 zip / 7z
  • 归档内的写操作会被拒绝并提示只读

传输与状态

  • 复制 / 移动 / 下载在服务端队列里跑，按字节报进度，可暂停、继续、重试、取消
  • 同名冲突提供保留两者 / 替换 / 跳过 / 取消；替换先落暂存目录再原子换入
  • 状态栏显示选中数量、文件 / 文件夹数、合计大小与磁盘余量

图标预览

仓库里的 scripts/icon-preview.mjs 会把每种扩展名、特殊文件名和一批真实文件生成到 D:\oriel-icon-preview，按 29 个分类目录排好，用来核对角标、页面比例与暗色表现。 

npm run icon:preview     # 生成样张目录
# D:\oriel-icon-preview\_全部扩展名      401 个文件
# D:\oriel-icon-preview\98-Office检查   系统图标 vs 自绘页一致性
# D:\oriel-icon-preview\99-徽标检查     {} </> 咖啡杯等符号角标

构建与发布

# 本地打包（前端 + 服务端产物 + 安装包）
npm run build
npm run build:desktop

# 打 tag 后由 GitHub Actions 构建并创建 Release
git tag v0.1.0
git push origin v0.1.0

应用内「设置 → 关于 → 检查更新」读取 ORIEL_UPDATE_REPO=owner/repo 的 GitHub Releases。GitHub 的下载域名在部分网络下不可达时，可以设置 ORIEL_UPDATE_CDN 指向自建镜像。

站点本身是一组静态文件（site/），推送到 main 后由 GitHub Pages 发布。

已知限制

  • Tauri 侧车尚未打包：桌面版目前需要本机有 Node 才能起 REST 服务
  • REST 服务未做多用户隔离，仅适合单机使用
  • Office / 可执行文件图标依赖 Windows Shell，非 Windows 环境会退化成自绘图标
  • 安装包未签名，首次运行需要在 SmartScreen 中选择「仍要运行」
  • 归档写操作只读，编辑归档内文件需要先解压
